S3.1 · What Is a Token

Tokens are the basic unit of data for LLMs.

AI doesn't deal with words but with numbers to predict statistically the next likely token. Every token is roughly 3/4 of a word[1] and represented as a unique number.

"Insanity is doing the same thing over and over again and expecting different results."
Ins anity _is _doing _the _same _thing _over _and _over _again _and _expecting _different _results .
≈ 0 tokens (approximate — every model splits differently) re-sent across a 50-turn agent session ≈ $0.0000 at Opus 4.8 input rates[7]

Every one of them is billed 4 ways

  • input every word you send — and re-send
  • output every word it says back
  • cache write storing context for reuse
  • cache read reusing it — ~10% of the input price[7]

S3.3 · What Is a Token

A hypothesis — not an accusation

The meter is hidden on purpose.

Follow the incentive. A vendor earns more every time you reach for a bigger model and burn more tokens — and the biggest vendors currently sell below cost to build the habit[10][11]. So the first taste is generous and the cost is abstracted away behind credits, vague limits, and a spinner where a number should be. You can't manage what you can't see. That's the hook.

01 The initiation

Unlimited, on the house. The intelligence feels like magic and the bill is invisible — so you build the habit.

02 The hook

Now you're fluent — and the meter's gone. Out of credits? Just top up. The number you'd need to push back never shows.

This is why the CLI meter matters: it's the one place the number is right in front of you — the same /context you just saw.

S4.1 · Managing Context

Context window is the model's attention span.

Picture the context window as a person's focus across a workday. It never starts empty — boot-up (system prompt, tools, skills, memory) already fills ~25% before you say a word; the /context readout you just saw was ~30% committed before a single message. Then every message resends the entire history, so the bar fills left to right: fresh at 9 AM, running on fumes by 5. A plain chat stays light; an agent balloons fast.

S4.2 · Managing Context

How key instructions get lost in the middle.

It's not a quirk — researchers measure a U-shaped attention curve[2], an uncanny echo of human memory. Models attend hardest to the beginning and the most recent; the middle blurs. A critical instruction buried ten messages back may as well not be there.

Primacy
the setup sticks
Recency
the latest is vivid
The lost middle
System prompt"You are an expert coder…"
[msg 12: read utils.js]
[msg 13: modify api.js]
[msg 14: read config.json]
Latest request"Why is the build failing?"
Same as people: you recall the first and last speakers in a long meeting, not the ones in between. Psychologists call it the serial-position effect[5] — primacy + recency — and the peak-end rule is its cousin.
Auto-compaction claws some back — partial, not guaranteed.[6]

S4.3 · Managing Context

Past ~half full, the model starts losing the plot.

Below that is the smart zone — grounded and reliable. Past it, quality degrades and the model starts filling gaps with plausible fiction; measured degradation begins well before the advertised window limit[3][4]. So do two things: monitor with /context, and compact via a handoff.

S7.1 · Tools & Tips

Two levers for context: automate vs. practice.

You can't ignore the context economy. Reclaim headroom by automating the heavy lifting, and establish team practices for leaner, more effective prompts.

Automated

  • Headroom High ROI

    Headroom compresses everything your AI agent reads — tool outputs, logs, RAG chunks, files, and conversation history — before it reaches the LLM. Same answers, fraction of the tokens.

  • rtk High ROI

    rtk filters and compresses command outputs before they reach your LLM context. Single Rust binary, 100+ supported commands, <10ms overhead.

  • Intelligent Routing (Prism, RouteLLM, OpenRouter) High ROI

    Dynamically route tasks to the most cost-efficient capable model per query.

  • Caveman Methods Net-Negative

    Blindly dumping entire repositories into context destroys output quality.

Team Practices

  • Edit, Don't Restart

    Edit the prompt that went wrong and regenerate. Stacking "no, do this instead" on top keeps the failed exchange in context — re-billed on every following turn.

  • Session Hygiene

    Start fresh sessions for new tasks instead of reusing bloated mega-threads — and don't leave a session idle mid-task: prompt caches expire within minutes, so coming back pays the full cold re-read[7].

  • Match Billing to the Work

    Flat-rate plans for open-ended, exploratory work; pay-per-token for well-scoped tasks. Don't pay by the token to wander.

  • Use CLI

    Work directly in the terminal for transparent token tracking and leaner context reuse.
