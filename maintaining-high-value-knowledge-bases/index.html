S1.2 · The Diagnostic Rubric

Personal Diagnostic Hypothesis · Author's Working Model

The Four Failure Modes: Pre-AI vs. With AI

A scoring rubric testing four pre-AI organizational failure modes against what generative AI actually altered: one solved outright, one holding strong, one split down the middle, and one amplified into a critical bottleneck.

01

Individual Protectionism

HOLDING

Pre-AI Baseline

Knowing the undocumented system was personal leverage and job security. “If I write it down, I become replaceable.”

With Generative AI Verdict: Holding

AI commoditizes generic snippet syntax, but repo-shaped architectural context remains in senior engineers' heads. Undocumented tribal context is still an intact moat.

02

Champion Tax

SOLVED

Pre-AI Baseline

Writing and structuring docs was unrewarded volunteer work. Helpful engineers paid the steepest tax, losing time from shipping code.

With Generative AI Verdict: Solved

Drafting is nearly free. Zero blank-page barrier: models generate initial schemas, turn PR diffs into draft ADRs, and summarize discussions effortlessly.

03

Discoverability + Trust

SPLIT

Pre-AI Baseline

Finding the right page was needle-in-a-haystack. And when found, nothing signaled whether it was current truth or 3-year-old dead fiction.

With Generative AI Verdict: Split

Discoverability is solved: vector RAG & hybrid search retrieve context in milliseconds. Trust is broken: agents swallow stale docs with 100% confidence.

04

High Maintenance Cost

AMPLIFIED

Pre-AI Baseline

Low initial drafting effort, exponential maintenance burden as code evolved. Docs decayed silently with zero compiler error or CI signal.

With Generative AI Verdict: Amplified

Generation outpaces verification. AI can generate 10,000 words in seconds, flooding repositories with unverified prose. The verification lag has become catastrophic.

S3.1 · The Axiom

The Dual-Track Requirement

Structure is mechanically checkable and meaning is not. You cannot deterministic-regex your way into factual truth — but you can enforce that trust metadata exists and is pinned.

Track A: Mechanical Governance

Frontmatter Linter

  • ✓ Validates YAML shape per path glob
  • ✓ Enforces status, verified.by, stale_after
  • ✓ Completely clock-free in CI (never fails builds)
  • ✓ Speaks human intent strings to agents
Track B: Semantic Verification

Human Verification

  • ✓ Named domain champion (verified.by)
  • ✓ AI pre-triages, human certifies truth
  • ✓ Stale horizons explicitly earned and lengthened
  • ✓ Truth remains human responsibility

S3.2 · The Engine

What the Harness Is

It is a config-based linter for frontmatter, and it does not know what OKF is. It enforces path globs, field constraints, and attaches human-authored intent strings. 

rules:
  presentation:
    paths: ["docs/presentations/**/*.md"]
    fields:
      status: { enum: [draft, stable] }
      stale_after: { format: date }
      verified: { fields: [by, at] }
    intent: >
      "Presentations must carry an expiration date
       and a verified human author before being delivered."

Click a Field Constraint

stale_after: <date>

“Every architectural document carries an expiry date. When past due, agents flag rather than trust.”

Prevents silent decay. Clock-free in CI to avoid turning code trees red overnight.

S3.3 · The Guardrails

What It Does Not Do

Candor reads as expertise. State the four design limits plainly:

✕ No Semantic Graders

Does Not Judge Truth

No deterministic tool can evaluate English truth. It guarantees trust metadata is present and pinned.

✕ Not In Read Path

Static Markdown Files

An agent that reads a markdown file in December sees stale_after has passed without running any tool.

✕ Clock-Free In CI

Never Fails on Expiry

If expired files failed CI, teams would just bump dates blindly. Freshness is an assessment, not a build gate.

✕ Verification Stays Human

Humans Own Currency

AI can pre-triage and accelerate drafting. Only a human domain champion can certify truth.
